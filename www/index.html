HTTPS on this network

Services here are served over both http:// and https://. The certificates come from this box's own authority, so a device has to trust it once. Install this, then https:// works with no warning:

navi-root.crtthe root certificate — install once per device

Verify it's the right one before trusting it. SHA‑256 fingerprint:
97:34:12:56:8C:A2:F7:3D:E2:3E:72:31:57:0A:44:30:6D:9B:44:70:D9:E4:19:30:EE:07:81:74:12:86:81:E1

music.lan is HTTPS-only. Jean needs a secure context for lock‑screen controls and media keys, and its foo_jean component has to share the page's scheme, so there's no working plain‑HTTP version. Without the certificate installed you'll get a warning. On a device that can't install it, go straight to the player at http://10.100.100.20:8880/jean.

If something is broken

This page cannot rescue you from DNS failure. If Pi-hole is down, no .lan name resolves, including this one. Two doors that stay open: http://navi.local (mDNS, doesn't touch Pi-hole) and http://10.100.100.53. Write the IP somewhere physical.
  1. "The internet is down." Check http://10.100.100.53:3001 first. If DNS · navi resolver is red, it's name resolution, not the internet. There is deliberately no secondary DNS, so a dead Pi-hole looks exactly like a dead internet.
  2. Need internet right now, bypassing navi. Set your laptop's DNS manually to 1.1.1.1. You lose ad-blocking and .lan names; everything else works.
  3. One ISP is down. The LINE monitors say which. The house keeps working on the surviving line — that's the point of two. Nothing is urgent.
  4. "ROUTE BROKEN" alert. The ER605 policy route for .61/.62 stopped working, so a per-WAN check is measuring the wrong line. Monitoring is degraded, the network is fine.
  5. navi won't boot. Pull the SSD and it falls back to the SD card (BOOT_ORDER=0xf14). The card holds a complete working system.
